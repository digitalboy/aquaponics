# 02_视频微服务一期实施计划 (Implementation Plan)

> **定位与关联**：本文档是视频监控与流媒体微服务（`video-service`）的中文工程实施计划，基于当前仓库既有的 `pnpm + Turborepo + Wrangler` Monorepo 结构编制，对齐 [README.md](./README.md) 与 [01_数据库表结构与边云控制协议.md](./01_数据库表结构与边云控制协议.md)。  
> **版本与状态**：`Version 1.0.0` | **适用分期**：`Phase 1` | **台账状态**：`Active`  
> **生效时间**：`2026-11-16T08:09:00.000Z` (严格遵循 ISO 8601 UTC)

## 1. Monorepo 代码落位规划

仓库根目录已具备 `apps/`、`packages/`、`pnpm-workspace.yaml`、`turbo.json`、`tsconfig.json` 与 `.wrangler`。视频微服务按职责拆分为三个独立包/应用：

| 目录路径 | 技术栈 | 运行位置 | 核心职责 |
| :--- | :--- | :--- | :--- |
| **`apps/video-gateway`** | TypeScript + Cloudflare Workers + D1 + R2 (`Wrangler`) | 云端边缘节点 | 统一对外 REST API、短时效签名鉴权、动态 `.m3u8` 生成、边缘心跳与 `agent_commands` 队列 |
| **`apps/video-agent`** | Python 3.11+ + `MediaMTX` + `FFmpeg` + `boto3/httpx` | 倍控 `N100` (Ubuntu) | RTSP 子码流复用、`tmpfs` 内存盘抓拍/切片、4G `snapshot`/`on-demand` 调度、断网缓冲淘汰 |
| **`packages/video-player`** | TypeScript + React (`hls.js` + Tailwind CSS v4 + shadcn/ui) | 嵌入各业务前端 | 统一播放器组件（支持 `waking` 状态等待、回放时间轴、C端脱敏水印）与 `iframe` 嵌入页 |

> **共享约束**：`apps/video-gateway` 与 `packages/video-player` 复用根目录 `packages/tsconfig` 与 `packages/schema`（定义严格 ISO 8601 UTC 校验与 API DTO）；所有 TypeScript 代码修改后必须执行 `npx tsc --noEmit` 校验零报错。

## 2. 分阶段里程碑与验收标准 (Milestones)

### M0：现场硬件连通与枪机参数摸底（前置准备）
* **触发条件**：`TP-LINK TL-TR904` 4G 路由器到货入柜，接入交换机 `Port 15` 并配置好流量卡（建议 `100GB+` 纯通用流量）。
* **实施动作**：
  1. 笔记本连 `TL-TR904` Wi-Fi，配置与倍控 `N100`（`192.168.1.50`）的 **SSH 免密登录**；
  2. 在 N100 上完成基础系统加固：`openssh-server`、`chrony`（锁定 UTC 时区）、`/mnt/hls_ram` `tmpfs (512M)` 挂载；
  3. 现场实测已安装海康枪机的真实静态 IP、RTSP 端口与账号密码，并用 `ffprobe` 核实子码流已设为 **`720p / 5 fps / H.264 / ~320 kbps`**（若仍为高码率则登录摄像头后台调低）。
* **验收标准**：从笔记本可无密码 SSH 登进 N100；`df -h /mnt/hls_ram` 显示 `512M tmpfs`；`ffprobe` 成功读出各在装枪机子码流信息。

### M1：边缘端拉流复用与内存盘零伤盘验证
* **实施动作**：
  1. 在 N100 部署 `MediaMTX`（systemd 托管），配置统一拉取海康枪机 RTSP 子码流并本地复用；
  2. 编写 `apps/video-agent` 核心模块：
     - `snapshot` 定时抓拍器（强制 `-an` 去音轨，输出至 `/mnt/hls_ram/snapshots/`）；
     - `hls` 按需切片器（输出至 `/mnt/hls_ram/hls/`）；
     - 内存盘水位守卫（超过 `80%` 即 `410 MB` 时按 FIFO 自动删除最旧文件，防止断网堆积撑爆内存）；
  3. 用 `iotop` / `iostat` 持续观测 1 小时，确认视频切片与抓拍期间 **128G 系统 SSD 写入量为 0**。
* **验收标准**：连续运行 24 小时无 OOM、无 `MediaMTX` 僵尸进程、SSD 无额外视频擦写。

### M2：云端 D1/R2 落地与 4G `snapshot` 模式上线
* **实施动作**：
  1. 在 Cloudflare 创建专用 `D1` 数据库与 `R2` 存储桶，并**立即配置 R2 前缀级 Lifecycle 自动过期规则**（`hls/` 7~15 天、`snapshots/` 90 天、`events/` 180 天），执行 [01_数据库表结构与边云控制协议.md](./01_数据库表结构与边云控制协议.md) 中的 `0001`、`0002` SQL 迁移与种子数据；
  2. 为 `video-gateway` 绑定自定义域名（一期暂用 `beikee.org` 子域，二期切换为 CF 独立注册域名；**禁止现场设备直连 `*.workers.dev`**），并在现场 4G 卡实测直连连通性；
  3. 开发并部署 `apps/video-gateway`：
     - 实现 `/api/internal/agent/heartbeat`、`upload-url`、`ingest`；
     - 实现 `GET /api/v1/cameras` 与 `GET /api/v1/snapshots/{cam_id}`；
     - 配置每日 Cron Trigger 清理 D1 过期索引记录（`hls_segments` / `snapshots` / 已过期 `agent_commands`）；
  4. 在 N100 开启 `snapshot` 模式（每 10 分钟抓拍 1 张传 R2），连续观测 24 小时 4G 流量消耗。
* **验收标准**：D1 可查询到带严格 ISO 8601 UTC 时间戳的快照记录；24 小时全厂抓拍+心跳总流量控制在 **`0.3 GB/天` 以内**（折合每月 `< 10 GB`）。

### M3：`on-demand` 按需直播与多系统嵌入联调
* **实施动作**：
  1. 在 `apps/video-gateway` 补齐 `/streams/{cam_id}/live`、`/playback`、动态 `.m3u8` 拼接与 `180 秒` 无观看自动下发 `sleep_live` 逻辑；
  2. 在 `apps/video-agent` 接入心跳指令消费器，收到 `wake_live` 后 `4~8 秒` 内起流推小分片；
  3. 开发 `packages/video-player`（Tailwind CSS v4 + shadcn/ui 风格），支持 `waking` 加载过渡动画、错误重试与 `iframe` 独立路由；
  4. 执行权限隔离安全测试：分别以 `internal_ops` 与 `public_viewer` 身份调用接口，验证 C 端身份访问正门/检验室机位必定返回 `403 Forbidden`，且 `public_trace` 播放流无音频轨。
* **验收标准**：在 4G 网络下从点击播放到首帧出图 $\le 10$ 秒；关闭网页 3 分钟后 N100 自动停流；C 端权限越权测试 100% 拦截。

## 3. 关键工程风险与应对红线

| 风险项 | 触发场景 | 应对策略 |
| :--- | :--- | :--- |
| **4G 断网导致内存盘写满** | 运营商信号中断数小时，切片无法上传 R2 | `video-agent` 设定 `tmpfs` 水位线 `80%`（410MB），超限按时间最早优先丢弃旧分片，**宁可丢云端缓冲也绝不让工控机死机**（本地海康 NVR 仍有 8TB 完整录像）。 |
| **海康枪机并发连接数超限** | 多个脚本同时直连同一个摄像头 RTSP | 严格规定**全机只允许 `MediaMTX` 直连摄像头**，其他所有 FFmpeg 抓拍/HLS 任务一律连接本地 `rtsp://127.0.0.1:8554/<cam_id>`。 |
| **C 端隐私与音频泄漏** | 摄像头自带麦克风或安防机位配置失误 | 代码层双保险：FFmpeg 命令硬编码 `-an`（当 `audio_enabled=0` 时）；Gateway 层对 `public_viewer` 强制过滤 `visibility = 'public_trace'`。 |
| **时间漂移导致图文错位** | 断电重启后未校时 | N100 强制开启 `chrony` + 硬件 RTC 兜底，且所有上报网关的数据强制校验 `YYYY-MM-DDTHH:mm:ss.sssZ` 格式。 |
